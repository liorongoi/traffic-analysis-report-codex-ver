| 6 | Full review UI, eligible datasets, training candidates/evaluation/promotion/rollback | Correction persistence, protected splits, real refit evidence | Partial: reviewers can explicitly label training/validation/test examples and assign them to verified camera views; the learning screen now inventories explicit human image labels by split, review completeness, task kind, duplicate source hashes and known camera/hour overlap. The night-light fitter and candidate inference bind to the saved manual view, alongside Fintraffic filename-derived views; the candidate is used only on its matching view and base proposals remain available for other views. The night-light inventory distinguishes fully reviewed from partially corrected sources for each evidence role, but fitting consumes only explicit eligible regions and never treats unmarked content in a partial review as negative. Night-head fitting and held-out evaluation now run as persistent background jobs with saved status, errors, and durable checkpoints. Startup requeues uncancelled interrupted tasks and resumes fitting from feature vectors plus optimizer state, or evaluation from cached features tied to the candidate and test-manifest hashes; work interrupted before the first checkpoint restarts from the beginning, and operator-cancelled jobs stay cancelled. Training and held-out evaluation cooperatively pause at feature-image and fit-step checkpoints when still-image or video inference needs the shared local worker slot, then resume when that operational run exits; the UI reports the yield. This preserves a single active processing worker while prioritizing operational inference. A mission-local night-light head can be manually fit from eligible labels, saves an immutable dataset/version hash, review-status provenance, algorithm/preprocessing/class configuration, explicit no-base-checkpoint rationale and a bounded CPU single-worker profile, then reports validation metrics. Training and validation each cap at 5,000 regions and source images at 24 megapixels; source images are feature-extracted one at a time. A candidate can be explicitly selected for later runs or disabled to return to the base context rules. A separate explicit action scores labeled light patches on the held-out set once per unchanged source/region manifest and records an immutable report. The append-only promotion/rollback ledger requires a current-manifest test evaluation, operator identity and rationale; a promoted candidate becomes the default selected option for future runs in that mission, while base rules remain selectable and each run snapshots its chosen model. Held-out evaluation compares against a distinct promoted night-light head when available and against saved linked base contextual-light proposals on paired held-out regions, with explicit coverage; neither comparison promotes automatically. The base comparison does not rerun full detection/background construction. The generic inventory does not imply that other algorithms have training adapters. A user-triggered COCO ZIP export now packages complete human-reviewed image evidence with protected train/validation/test roles and refuses known split leakage; this is data packaging. An optional YOLOX-S fine-tuning CLI now consumes the training and validation splits only, exports an ONNX candidate pack, and supports mission-local operator import/selection for future still-image runs with frozen run hashes.
