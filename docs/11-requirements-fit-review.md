# Requirements fit review — 2026-10-25

This review compares the current project state with the verbatim product request in [requirements-source.txt](requirements-source.txt). It describes the implementation in this workspace, not the full requested production system. Evidence from [vehicle detection](10-vehicle-detection.md) supersedes earlier foundation-only statements where they conflict. The original product requirements remain controlling; a prototype or passing test does not waive them.

## Fit summary

The repository is a valid independent, still-image review and inference increment. It is not yet a production-ready match for the full request. It has a real local CPU vehicle-proposal adapter and an experimental light-candidate path, plus source snapshots, per-mission stores, revisioned review, and CSV/report output. Results are explicitly proposals and are not validated counts.

## Alignment issues to keep visible

All shipped algorithms now expose a structured learning-capability declaration in the API and learning panel. The declaration identifies that the night-light head supports downstream-classifier training, the per-view background builder supports run-scoped background refitting, and other shipped detectors/heuristics currently lack training or calibration adapters. It explicitly records that YOLOX fine-tuning is not implemented. This metadata improves capability traceability; it does not close model promotion, representative-data, or accuracy gates.

Video event timing trims and track identity edits are implemented as append-only corrections. Timing trims snap to saved same-track observations; merges create one corrected logical event; splits create child events at a saved analyzed frame. Event browsing, clip boundaries, and CSV/XLSX exports use corrected identities while retaining original event IDs and review history. Representative media, accuracy and native Windows acceptance remain open.

- The README and `docs/10-vehicle-detection.md` describe the current real inference increment. Older planning text in documents 01, 05, 06, 08, and 09 must not claim that no adapter exists or that the detector is already accepted as a production capability.
- The 143-image sample run proves that the adapter processed those files. It does not prove detection accuracy, night performance, traffic counts, Windows compatibility, GPU support, or a complete offline deployment.
- Remaining operational inputs include representative video/codecs, verified capture UTC origins and duration, daily volume/history size, training/reuse policy, and numerical acceptance thresholds. Current instructions settle no-admin installation, while video clip context is explicitly entered per export. Public sources inspected so far include [HVSD](https://data.mendeley.com/datasets/zdgmdg7p25/1) and [Oran road recordings](https://data.mendeley.com/datasets/8k86t83wy5/1), both CC BY 4.0 but without capture UTC metadata, and [Zenodo Dataset for Traffic Evaluation](https://zenodo.org/records/14041920), whose filenames contain apparent times but whose record does not specify a license or time zone. Do not treat filename times as UTC or use unclear-rights media as acceptance evidence.
- The next product gates are: validate PTS tracking and event duplicate behavior on authorized representative recordings; obtain authorized representative video for traffic acceptance and plate-localization samples for the four target countries; resolve the training/reuse/promotion policy and complete the learning lifecycle; then validate the packaged offline Windows/LAN deployment and 16/48 GB hardware behavior. A new possible fixed-camera/UTC lead, [VIDETEC-2](https://zenodo.org/records/17799385), describes eight infrastructure-mounted HD cameras and UTC epoch synchronization, but its Zenodo license field is blank and the camera-video-to-UTC/PTS mapping is not confirmed; it is not approved for use unless those gaps are resolved. Source-to-export and application-storage overlap is rejected to prevent recursive self-ingestion; source rename reconciliation now offers explicit reversible links for byte-identical records while preserving each capture. Held-out camera-view proposal quality remains open.
