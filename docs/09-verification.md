## Conservative video tracker foundation — 2026-10-25

Added a same-recording tracker that accepts normalized detections and an explicit policy (`max_gap_seconds`, IoU and center-distance limits, ambiguity margin, and any compatible label groups). No threshold defaults are embedded. Matching state can be serialized as JSON and restored only for the same run and exact policy, preserving track IDs across processing chunks; a changed/corrupt checkpoint is rejected. Frames must have monotonic PTS-derived offsets. Ambiguous competing tracks or detections create separate uncertain fragments rather than a forced merge. `finish()` closes active tracks at recording boundaries and at detected scene cuts. Scene detection compares sampled RGB histograms frame by frame, exposes an adjustable threshold in the video run/continuous policy, and seeds its comparison from skipped frames when resuming. A cut closes current tracks with a `scene_cut_boundary` uncertainty reason before assigning new detections, preventing automatic identity links across shots. It does not implement cross-camera or cross-recording matching. Scene-cut fixtures cover brightness and color changes, no association across cuts, and resuming immediately before a cut; representative-video sensitivity remains unaccepted. The full suite contained 112 checks after this increment; production tracking behavior remains unaccepted until evaluated on authorized, representative videos.
