# Traffic Analysis — independent offline application

## Working inference and review preview (2026-10-25)

This is a **separate project**, outside SpectraScope. Its source, workspace, database, launch port and installer identity are independent.

Implemented:

- Browser review interface with English/Hebrew switching, RTL/LTR layout and directionally isolated timestamps/filenames.
- Mission setup stores input type, one analysis mode, location/time zone, source/output paths, recursion, processing preference and export formats in a per-mission SQLite configuration. It searches 34,188 GeoNames cities across 244 country codes plus installed IANA zone names, and previews UTC-to-local offsets/DST. The offline map includes 239 country shapes and 419 approximate IANA timezone regions worldwide; country and timezone fields remain editable. The backend validates configured directories and prevents image import or inference for unsupported mission types/modes.
- Import batches remain separate runs; non-recursive image imports honor the saved mission setting.
- Explicit camera filename parser (`DDMMYYYY-HHmm-suffix`, UTC minute precision) and explicit Fintraffic manifest importer (UTC second precision).
- Recursively import camera images. Fintraffic imports verify every image against its provided SHA-256 manifest. Originals stay untouched; independent mission snapshots are verified again when viewed.
- Image table and previous/next review; draw/remove normalized image rectangles; distinguish confirmed vehicles, candidates, lights and background lights.
- Append-only review revisions, operator, evidence role and completeness. Optimistic revision checks prevent overwriting concurrent edits; held-out image roles cannot become training roles. An explicit bulk sign-off path previews the saved run, exact image count, and fixed row boundary, requires operator confirmation, exports only that snapshot, and labels it `bulk_unreviewed` rather than independent ground truth.
- Traceable CSV snapshots written to the configured output folder with unique filenames, source IDs/checksums, revision state, and a snapshot hash. Machine proposals remain explicitly unconfirmed until a human reviews them.
- Loopback development host with a session token for writes, host/origin checks and self-only browser asset policy.
- Real local YOLOX-S vehicle inference, separately labelled experimental night-light proposals, durable progress/cancellation, immutable original predictions and saved correction lineage. See [vehicle detection and testing](docs/10-vehicle-detection.md).
- Bounded PyAV/FFmpeg video decoding that yields one RGB frame at a time and preserves each frame's exact integer PTS and rational time base; generated VFR regression coverage confirms uneven timestamp gaps. Absolute UTC still requires a supplied recording origin.
- Policy-configured, same-recording track assembly with JSON-compatible chunk checkpoints. Ambiguous associations remain uncertain; thresholds must be supplied explicitly and are not production-validated.
- Incremental video analysis connects the spawned decoder to the detector and tracker, lets operators select supported vehicle classes per immutable run, reports per-frame position/progress, supports cancellation, and leaves absolute UTC unset without an explicit origin. The spawned decoder process isolates bundled FFmpeg libraries from OpenCV.
- Per-mission video evidence copies, immutable run snapshots, atomic per-frame detection/track/event checkpoints, idempotent events, and append-only event-review records. Video Traffic runs use a supervised child worker, persist model/tracker settings, share the single local processing slot with image inference, and expose source/run/event-review APIs. The browser supports source registration with UTC-origin provenance, run settings and lifecycle controls, paginated event review with clickable verified source-frame previews, the associated video filename, playback seeking five seconds before the event, saved detection boxes/track labels over analyzed playback frames, integrity-checked byte-range playback, and event clip exports. Live overlay data is saved per analyzed frame and is not interpolated. Exports use explicit operator-entered pre/post context, encode video-only H.264 MP4, and record event/run/source lineage plus a SHA-256 output hash in the mission ledger.
- Saved video runs export configured CSV/XLSX event tables with links to the source, run, current review revision, and related clips. Files go to the configured output folder, use unique names and snapshot hashes, and recover interrupted publishing. Plate handling extracts image chips and offers local OCR suggestions for Latin and Arabic/Persian letters with digits; reviewers separately approve chips and accept, correct, reject, or mark text unreadable.
- The still-image results table can search and sort by filename, capture time, camera view, proposal counts, processing status, and review status. Processing and review state are shown separately.
- Mission-scoped offline object search filters supported categories, operator-recorded visible colors/subtypes, and saved schedule/view scope. Detector output does not infer color or fine subtype; unrecorded values stay uncertain.
- Windows **preview installer source** with current-user privileges, app-local runtime, exact dependency pins, offline payload manifest, both detector packs, install-time integrity/model checks and receipt-gated launch. It is not a finished installer until built and accepted on Windows.

## Run the preview

Requires Python 3.11+ and installed IANA timezone data. On Windows, the eventual private runtime must include `tzdata`; installation must not download it.

```sh
PYTHONPATH=src .venv/bin/python -m road_traffic serve --workspace workspace/sample-review --port 8765
```

Open http://127.0.0.1:8765 in a browser. The default development preview binds **only to loopback**. An opt-in single-operator LAN mode is available with `--host 0.0.0.0`, an exact browser-facing `--public-host`, a trusted TLS certificate/key, and `TRAFFIC_ACCESS_CODE` set to at least 16 characters. For example, on PowerShell, set the access code in the current shell before launch, then provide `--tls-cert` and `--tls-key`; never put the secret on the command line. LAN sessions use HTTPS-only, HttpOnly, SameSite cookies and expire after 12 hours. Provide the certificate through an organization-approved trust chain and restrict the host firewall to authorized clients. HTTPS integration tests cover the local sign-in/session flow; native two-computer and Windows acceptance remain pending.

In this workspace, use the neutral development runtime at `/Users/lioron/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3` if system Python is older than 3.11.

Fintraffic samples supplied by the user are imported locally into `workspace/sample-review`. They are not installer defaults. The initial failed development import is retained as a separate empty mission/run record for diagnosis; select the mission containing 143 images.

## Not implemented yet

Interrupted inference runs preserve per-image results and can resume unfinished inputs under the original immutable run configuration. Continuous still-image intake runs in the backend; it fully decodes JPEG/PNG files up to the current 24-megapixel limit before import, reports invalid paths, and lists missing source paths without deleting imported evidence. When byte-identical images reappear under a different path while the old path is missing, the monitor offers an operator-confirmed, reversible source link with captured paths, snapshot IDs and checksum; both image records and review histories remain separate. Continuous still-image batches queue source-scoped General Traffic runs. Continuous Video Traffic missions can monitor stable files after the operator saves an explicit detector and tracker policy; each imported video gets a private immutable snapshot and durable queue record with a frozen policy, then starts analysis when the shared worker is free. Changed video content remains a separate source version. Operators can pause/resume either monitor, and queue status plus new-data/completion/failure events appear in the app. Watchdog filesystem notifications wake scans early; periodic reconciliation remains active, with an explicit polling-fallback status when notifications cannot be established. The mission wizard includes an offline world map with country outlines and approximate IANA timezone regions; map clicks select country, coordinates, and timezone where boundaries are available, while city search resolves the exact GeoNames location and IANA zone. Operators can edit country and timezone values and preview UTC-to-local time across historical DST transitions. Local-time scanning windows are applied to inference runs; operators can create/split/reassign camera-view groups and merge groups with audited assignment history; saved run snapshots stay unchanged. View-specific, validated inclusion/exclusion polygons are revisioned and snapshotted into inference runs; changed ROI geometry flags affected runs, and operators can acknowledge the exact change and launch an audited rerun over the same inputs while model settings match. CSV and XLSX exports write Unicode-preserving, non-overwriting snapshots into the configured output folder and record their checksums in the mission ledger. Export rows are written in bounded batches. Overnight windows use the selected start weekday; boundaries are start-inclusive/end-exclusive; daylight saving uses the mission's IANA zone. Native Windows notification acceptance, held-out camera-view grouping acceptance, per-view background accuracy acceptance, production continuous-video acceptance, validated night traffic counting/tracking, authorized target-country plate-chip quality acceptance, open-ended natural-language schedule/region parsing (explicit weekdays, ISO dates, 24-hour windows, and named saved views are supported), YOLOX fine-tuning/automatic model promotion, and native two-computer LAN acceptance remain outstanding. Authenticated HTTPS LAN mode is implemented with a local smoke check. Experimental light candidates are not validated detections. See [bundled map data provenance](docs/third-party-data.md).

Video source/run/event storage is connected to a supervised child worker and authenticated local APIs for source registration, run start/status/cancel/resume, and append-only event review. Orphaned workers are reconciled as failed resumable runs while preserving frame checkpoints. The browser provides video source registration, run configuration and lifecycle controls, paginated event review with verified source-frame previews, integrity-checked playback and event seeking, and H.264 MP4 event-clip export with explicit pre/post context and a mission-local integrity ledger. Representative-media/UTC acceptance remains incomplete; see [the requirements fit review](docs/11-requirements-fit-review.md).

The current development inference runtime is the independently staged `.venv`. `requirements-inference-macos.lock.txt` records its packages; installed runtime code never invokes pip.

The on-demand host report reads CPU, RAM, GPU/driver inventory, runtime provider names, and free disk capacity. It also shows advisory conservative 16 GB and expanded 48 GB memory budgets. Each still-image/video run can use Auto, Conservative (one ONNX thread), or Expanded (up to four threads); continuous still-image missions save the profile at setup, and continuous video stores it with the detector/tracker policy. All profiles keep one worker, and the selected limit is saved in each run snapshot. GPU remains disabled until execution is validated. The report recommends CPU until execution is probed, then measures a small temporary write+fsync and immediate read on the application-data volume. The read may be served from the OS cache, so this is a local comparison aid rather than a sustained-storage benchmark. Provider listing does not prove GPU execution. During active image/video work, the progress line also reports worker resident memory and sampled CPU use as a share of total logical-core capacity when OS process inspection succeeds; unavailable measurements are labeled. This process telemetry is not GPU usage or full-system load. Native Windows target measurement and GPU execution remain unverified.

The Windows setup EXE has **not** been built or tested. It requires a complete Windows x64 runtime and timezone pack staged independently, Inno Setup compilation, extracted-payload inspection and a native no-admin/offline Windows test. The preview uses an existing browser; the final application/browser-engine packaging is still outstanding. Do not use the setup source as proof that the finished offline application exists.
